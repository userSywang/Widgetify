# 启动屏幕绑定恢复

本次修改仅涉及 `InspirationIntegration.swift` 的启动布局恢复，不改变组件 UI、拖动或 Notion 功能。启动恢复位于灵感首次添加判断之前，因此已完成初始化的现有安装也会运行检查。

仅在当前只有一个活动显示器、布局中所有组件同属一个已失效屏幕标识时迁移。保留组件编号、类型、内容、设置和大小；屏幕尺寸及坐标相同则只修改屏幕标识。尺寸变化时保持相对位置并将越界位置限制在当前屏内。多屏、混合旧屏幕归属、无活动显示器或损坏数据不自动迁移。此版没有实现显示器热插拔监听，也不保证大于屏幕的组件能完整显示。

写入前将原始字节备份至容器 `Application Support/Widgetify/ScreenRecovery/layout-before-<UUID>.json`，备份失败则不修改原布局；写入前再次核对原文件，避免覆盖准备期间发生的编辑。正确绑定后重复启动不再生成迁移或备份。

验证：`scripts/test.sh` 全部通过。隔离副本 `outputs/screen-recovery-preview/Widgetify 正式接入预览.app` 仅创建一个灵感宿主，用虚构旧屏幕标识启动，已确认自动恢复到当前屏幕且原布局备份一致；第二次启动无重复备份。证据为同目录 `recovery-check.json`。用户确认后已替换 `/Applications/Widgetify 0.2.13.app`，保留版本号和启动路径；仅更新经预览验证的 Context 模块及其签名。旧软件、配置、布局与私人灵感数据备份于 `work/backup-screen-recovery-install-20261117-212702`。重启后系统窗口清单确认 10 个桌面组件显示，布局与灵感记录和安装前一致。未推送或发布。
