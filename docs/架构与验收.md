# 0.2.4 架构与验收

## 接入边界

原厂主体仍是编译后的 Swift/SwiftUI/AppKit 程序。新增代码完整位于本仓库，不能声称已经取得原厂完整源码。

WidgetContext 从原 GenericWidgetifyView 的反射元数据读取 WidgetModel.id，识别 WaterController / DocumentController，读取可访问的组件配色。原组件菜单调用它本身的设置回调，避免模拟鼠标、按坐标识别窗口或创建平行设置窗口。

ComponentIntegration 仅对已识别原组件的 WidgetSettingsPopoverPresenter 弹层增加分段入口，原设置控制器保持为子控制器，保留原生命周期与滚动。其他弹层不包装。

新增引用通过原卡片的 NSDraggingDestination 导入接口处理。DirectoryReferences 仅对登记的目录操作，将原导入流程的搬移/复制替换为带所有权记录的隐藏符号链接；原目录不搬移、不复制，原控制器负责加入列表、显示和持久化。系统文件定位会将本模块的引用还原到原目录。

原卡片显示和原设置保留，不关闭或重建原窗口，也不直接改写原控制器的引用文件。前期窗口重建方案因原设置生命周期不兼容而未采用。目录拖入保护挂接于当前系统的 SwiftUI 拖入目标；建议使用组件内明确的“添加文件夹引用”按钮。

这属于绑定受支持版本的运行时集成，并非原厂公开插件接口。升级基础程序前必须重新验证，不能删除代码指纹校验后直接复用。

## 数据链

- 原组件清单：Application Support/Widgetify/autosaved.widgetlist4。
- 原引用：Documents/widgetify/组件ID；访问书签：同名 _bookmark。
- 提醒设置：custom.component.组件ID.water。
- 文件夹隐藏设置：custom.component.组件ID.folders.hideDesktop。
- 恢复记录：custom.enhancements.folders.v1，只恢复 hiddenByUs 的目录。
- 受管理引用：custom.references.links.v1，保存原目录访问书签、链接路径及设备/inode 所有权；移除后清理本功能的链接，原目录保留。
- 访达入口：桌面目录，带本模块所有权清单；替身目标验证后才允许隐藏。

多个卡片引用同目录时，只要其中一个启用隐藏就保留隐藏；所有引用移除或均关闭隐藏后恢复。软件正常退出统一恢复，但保留选项供下次启动使用。异常退出后入口不依赖进程存在。

## 0.2.5 喝水专项更新与验收

新增 WaterPresentation.swift，使用 SwiftUI 原生行式控件构建提醒页，仍挂在原组件弹层内。实时缩略图只读取原组件 NSView 的当前渲染结果，不重新承载 GenericWidgetifyView，不重建原控制器；预览关闭后原容量、蒙层和外观设置仍实际可见。

调度配置增加 scheduleVersion=2、intervalMinutes、nextReminderAt、lastReminderAt。原每日时点字段不再参与触发。外观改动保留到期时间，间隔/开关改动才重新安排；长时间休眠、启动过期与时钟回拨跳过积压。

实际验证：1 分钟间隔自动显示提醒；10 分钟延后更新下一次时间；卡片和轻提示显示原组件画面；手动关闭与 10 秒自动关闭生效；切回原设置仍显示 300 ml 容量、3000 ml 目标与原猫形蒙层。本机最终恢复为 45 分钟、卡片 10 秒、声音开启。原饮水记录仍为 0，预览未增加记录。

间隔单元检查覆盖提前、跨越、启动过期、长时间睡眠、样式改动保留到期时间、间隔改动重新安排与非法零间隔。原目录引用与桌面路径保护检查继续通过。多显示器、不同自定义蒙层和长时间功耗仍未穷举。


## 0.2.6 快捷启动分类

识别原 AppController 所属组件，分类元数据使用独立键 custom.component.组件ID.launchCategories.v1；只读取原组件 ID 对应的应用 URL 数组，不改写该数组。右键分类菜单仅拦截快捷启动原窗口的右键事件，其他窗口保持原处理方式。原设置回调通过菜单底部“组件设置与分类…”保留，弹层新增分类页。

已实际验证分类新增、改名、顺序调整、删除、把访达分配到常用，以及从常用菜单实际打开访达。正常退出、重新启动后该分类分配保留；随后已清除测试分类与访达测试分配。与升级前备份比较，原 13 个应用的 URL 列表和排序完全一致。

本版本为右键菜单分类，桌面原网格仍显示原全部应用；顶部分类标签、按类过滤原网格、分类内拖动排序未实现。没有替换或重建原快捷启动控制器。


## 0.2.7 卡片内分类

ShortcutCategories.swift 增加自有 SwiftUI 分类按钮和图标展示层，读取原 AppController 的有序应用 URL 数组；筛选结果保留源顺序，剔除不再被组件选中的旧分类引用。分类选择保存在独立 launchSelection.v1 键。未保存过的默认分类使用稳定 ID，避免扫描刷新重置选择。

原生 NSHostingView 和控制器保持存活且同尺寸布局，位于容器内；通过源视图 alpha 隐去重复图标，原设置回调仍从源视图查找。不能限制整个容器的 accessibilityChildren 为新增展示层，否则原 SwiftUI 设置的可访问内容也会被排除。没有复制或重建原 SwiftUI rootView 或写入私有对象内存。原设置改变尺寸而更换源视图后，组件扫描重新附加展示层。

卡片内直接切换分类、原生设置按钮、右键设置、常用分类只显示访达、点击访达启动、重启分类保留、紧凑模式和带名称模式、M/L 尺寸切换均已实际验证。测试归类已清除，组件恢复 M、紧凑图标，选中全部应用。原应用数组与升级前备份一致。

分类筛选的全部、未分类、指定组、删除分类回退、组件移除应用后不再显示旧引用有自动断言；原间隔提醒、桌面边界与受保护目录引用测试继续通过。背景图片读取兼容代码已构建，未对所有图片模式或所有尺寸组合做完整视觉验收。


## 0.2.8 保留原生背景

移除 InlineLaunchCard 的自有全卡背景色、背景图片、NSVisualEffectView/HUD 材质和圆角背景实现。原 source.alphaValue 保持 1，只把源视图内的 NSScrollView 应用网格 alpha 设为 0。原 GenericWidgetifyView 下的 BlurView、WidgetBackgroundModifier 及背景图层保持可见；新增分类和图标为透明内容。无需追踪、复制或模拟原背景参数。

已经实际确认源视图中原 BlurView/NSVisualEffectView 与应用 HostingScrollView 是分开的视图。复查原设置弹层，背景模糊 on/off 可切换；在自定义颜色中 A 从 100% 改为 40%，实际背景随之变化，再恢复 100%。与修改前备份比较，原 bgColorKey、bgBlurEnabledKey、compactIconsEnabled 和应用数组完全一致。
