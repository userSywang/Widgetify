# 0.2.4 架构与验收

## 接入边界

原厂主体仍是编译后的 Swift/SwiftUI/AppKit 程序。新增代码完整位于本仓库，不能声称已经取得原厂完整源码。

WidgetContext 从原 GenericWidgetifyView 的反射元数据读取 WidgetModel.id，识别 WaterController / DocumentController，读取可访问的组件配色。原组件菜单调用它本身的设置回调，避免模拟鼠标、按坐标识别窗口或创建平行设置窗口。

ComponentIntegration 仅对已识别原组件的 WidgetSettingsPopoverPresenter 弹层增加分段入口，原设置控制器保持为子控制器，保留原生命周期与滚动。其他弹层不包装。

新增引用通过原卡片的 NSDraggingDestination 导入接口处理。DirectoryReferences 仅对登记的目录操作，将原导入流程的搬移/复制替换为带所有权记录的隐藏符号链接；原目录不搬移、不复制，原控制器负责加入列表、显示和持久化。系统文件定位会将本模块的引用还原到原目录。

原卡片显示和原设置保留，不关闭或重建原窗口，也不直接改写原控制器的引用文件。前期窗口重建方案因原设置生命周期不兼容而未采用。目录拖入保护挂接于当前系统的 SwiftUI 拖入目标；建议使用组件内明确的“添加文件夹引用”按钮。

这属于绑定受支持版本的运行时集成，并非原厂公开插件接口。升级基础程序前必须重新验证，不能删除代码指纹校验后直接复用。

## 数据链

- 原组件清单：Application Support/Widgetify/autosaved.widgetlist4。
- 原引用：Documents/widgetify/组件ID；访问书签：同名 _bookmark。
- 提醒设置：custom.component.组件ID.water。
- 文件夹隐藏设置：custom.component.组件ID.folders.hideDesktop。
- 恢复记录：custom.enhancements.folders.v1，只恢复 hiddenByUs 的目录。
- 受管理引用：custom.references.links.v1，保存原目录访问书签、链接路径及设备/inode 所有权；移除后清理本功能的链接，原目录保留。
- 访达入口：桌面目录，带本模块所有权清单；替身目标验证后才允许隐藏。

多个卡片引用同目录时，只要其中一个启用隐藏就保留隐藏；所有引用移除或均关闭隐藏后恢复。软件正常退出统一恢复，但保留选项供下次启动使用。异常退出后入口不依赖进程存在。

外部移动或重命名被引用目录后，隐藏的符号链接可能失效，需从组件移除入口后重新添加；原目录和内容不会由本模块搬移或删除。该场景不标记为已完整解决。
