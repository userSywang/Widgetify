# 灵感与 Notion 双向同步候选

用户确认本次具体预览后，已安装 `/Applications/Widgetify 0.2.15.app`。下文保留隔离预览验证过程；未推送或发布 Release。

## 行为

- Notion 数据库的新记录自动进入灵感；完成远端全量扫描后，本地尚未关联的有效记录进入上传队列，历史页面优先按编号或完整原文关联，避免重复创建。
- 同步标题、原文、详情、分类、日期、状态、优先级及可解析的补充文字。组件的展开弹层增加“修改原文”、详情、状态和优先级编辑，仍使用原弹层和公共样式。
- 两边删除对应同一 Notion 页面的垃圾箱状态；本地保留内部删除标记以继续识别页面恢复，组件不提供最近删除或删除恢复入口。在 Notion 恢复后重新显示同一条，不重新创建页面。
- 本地删除尚未上传的记录时，恢复连接后先建立对应页面再移入 Notion 垃圾箱，使恢复仍有入口。离线任务保留在本机。
- 远端查询中缺席不能证明删除；已关联但查询不到的页面单独读取，只有成功读取到明确垃圾箱状态才同步删除。404、403、断网均保留本地记录。
- 每 30 秒检查；请求进行中合并定时重试，网络和数据量会影响实际完成时间。没有使用 AI、聊天连接器或公网 webhook。

## 数据保护

同步关联增加可选基线，兼容 0.2.14 配置。记录分别缓存上次读取的 Notion 标题与原文：真实测试发现更新时间只有分钟粒度，且标题和正文可独立修改，因此不能只看更新时间，也不能仅以本地文本推断远端标题变化。

本地编辑与远端编辑相对同一基线比较；不同补充可合并，同一内容的冲突保存两版，在原灵感设置中选择“采用 Notion”或“保留本地”。选择前显示完整两版文字及属性；选择后也把两版另存至私密 SyncConflicts。发送前再次读取复核；Notion API 不提供本实现可用的原子条件写入，极短的检查后竞态仍不能完全排除。

远端更新先写入持久 inbox，再在组件线程核对本地是否仍等于预期版本。应用前备份原文档至私密 SyncHistory；本地已经有新修改则不覆盖。编辑弹层保存时也核对开始编辑时的版本，避免覆盖编辑期间刚读入的远端更新。私人 Git 历史保持独立，仍由原功能保存。

复杂媒体继续保留在 Notion；组件以文字呈现可解析的块，不提供完整 Notion 富文本排版。嵌套读取有深度和数量保护，读取失败不按空内容覆盖。Notion 旧的追加内容兼容迁移，正文中不再新增可见同步编号。
