# 灵感：本地记录与 Git 历史

当前交付为已确认并安装的正式0.2.11，使用原组件背景和模糊。下文早期预览的容器路径保留作迁移说明，正式数据位置见v0.2.11一节。新增源码属于本项目，不是恢复出的原厂源码。

## 使用

在灵感卡片右上角“···”菜单选择：

- 保存到 Git：为当前全部已保存的灵感、标签、补充和归档状态保存一次历史快照。
- 查看本地历史：在组件弹层里查看最近30次提交及当时的完整文字，可复制内容；“打开保存目录”可找到 Markdown、JSON及完整 Git 仓库。30次只是界面显示数量，不删除旧提交。
- 灵感设置：沿用原组件的外观入口，并提供上述本地历史入口。

新增与补充输入自动暂存在本地，关闭编辑后可继续写。保存补充后，草稿才被清除。展开思路可以阅读原文与全部补充。Git快照不包含未提交草稿和当前选中项；切换下一条不会改变历史内容。相同内容不会重复提交。

本地记录自动保存与 Git 历史是两件事：点击“保存到 Git”才留下当前快照。Git失败不回滚或删除本地记录，状态会提示重试。当前仅支持查看历史与复制旧内容，不提供一键覆盖恢复。

## 存储

预览独立容器内：

`~/Library/Containers/local.widgetify.stylepreview.inspiration.nov15/Data/Library/Application Support/InspirationPreview/`

- `ideas-v1.json`：本地记录、原文补充、两类草稿与选中状态；原子写入。旧版没有补充草稿字段也能读取。
- `LocalHistory/`：独立 Git 仓库。
- `LocalHistory/灵感.md`：可阅读的全部记录。
- `LocalHistory/records.json`：包含ID、时间和归档状态的完整快照。

预览更新沿用同一独立容器，保留用户已经输入的内容。这个仓库没有远端，不操作本软件源码仓库，也不上传内容。本地历史仍在这台电脑，手机及云端同步暂未实现。

## 实现和验证

`InspirationHistory.swift`仅在专有标记的目录内工作，拒绝接管已有无关目录。Git通过独立参数调用，不拼接命令文本。禁用外部hooks、签名与全局配置，Git操作在串行后台队列运行，界面不等待进程完成。

系统Git在应用限制下无法初始化，预览改为携带本机开发工具中的Git，子程序继承同一应用限制；未放宽权限、未申请网络权限。

已通过 `scripts/test.sh`：已有提醒/路径保护回归、本地记录、中文草稿及重启、补充保留原文、归档恢复、损坏文件保护、Git无重复提交、多个历史快照、旧内容保持、无远端、无关目录保护、失败后重试。

实际界面已操作验证：保存历史成功、相同内容不重复提交、历史弹层读取、退出重启后历史仍可查看，用户原有补充保留。当前安装版两个增强模块的SHA-256与此前批准版本相同。

## 私人项目边界

灵感组件保留在本软件中，内容属于独立本地私人仓库，和软件源码项目分开。目录权限限制为当前账户访问（700），记录文件为当前账户读写（600）；读取已有记录时也收紧权限。没有配置Git远端，没有建立GitHub项目，也不会随源码推送上传。这是本地访问控制，不是额外的内容加密。

## v0.2.10 公开预览附件

正式安装包目前只接入喝水圆角修复和已有功能；灵感通过单独预览附件提供。公开预览标识为 `local.widgetify.stylepreview.inspiration.public`，使用通用示例，和本机已有的私人预览容器分开。

公开包不读取本机配置进行打包；它在首次运行时取得使用者自己的屏幕标识。其 Git 工具从未修改的上游 Git 2.50.1 源码构建，许可证随应用提供，完整源代码 `git-2.50.1.tar.xz` 作为同一 Release 附件提供。构建方式记录于应用内 `Contents/Resources/ThirdParty/Git-source.txt`。

制作公开预览时为构建脚本提供 `--public --git-executable <已构建的Git路径> --git-source <上游源码归档路径>`，不应发布使用开发机配置制作的本地预览。

## v0.2.11 正式接入

正式模式不读取示例种子，记录使用正式容器的 `Application Support/Inspiration/`。组件首次自动加入，应用菜单“灵感组件…”可打开；在组件设置中隐藏后，可以从此菜单恢复。内部沿用原生快捷启动宿主，原厂组件选择器没有增加新类别。

组件布局追加前备份原文件到 `Widgetify/InspirationIntegration/layout-before-v1.json`，保留原组件对象及配置。布局损坏时不覆盖；已添加过的组件不会在重启时重复加入。

安装前使用 `scripts/install_local.py` 生成计划。经用户对具体候选包确认后，再传入 `--apply --expected-app-sha256 <计划中的值>` 执行。安装程序要求旧正式软件已关闭、安装目录不存在、正式灵感记录为空，并先备份原应用及配置。安装副本指纹核对和迁移成功后，才将新应用放到最终位置，不自动启动或发布。

迁移保留 `ideas-v1.json` 与整个独立 Git 仓库，迁移前后检查源内容一致及 Git 对象完整，不覆写源目录。遇到目标已有记录、目录链接、未完成的Git写入、远端配置或外部对象库时停止。正式安装后，旧预览数据仍留在原容器中，作为额外恢复来源。
